## Conclusión y alcance de la causa

Claude Code 2.1.295 reconoce la sesión propia `claude.ai` fuera del sandbox.
El entorno mínimo de cuatro variables utilizado por el smoke omite `USER`.
En consultas locales de `auth status`, añadir **solo USER** al entorno mínimo
restaura el reconocimiento; retirarlo del entorno de la sesión lo impide.
`LOGNAME` por sí solo no lo restaura. Esta dependencia está comprobada para
este binario/Mac mediante comparaciones controladas, sin leer credenciales.

La omisión de USER es una causa reproducible de la falta de sesión en el
entorno mínimo, coherente con D022. No se ha demostrado el mecanismo interno
del binario ni repetido el argv de inferencia D022. No procede pedir al usuario
que vuelva a iniciar sesión: la sesión ya se reconoce en su contexto habitual.
La corrección del entorno y la regresión offline se proponen por separado.

## Reproducción limitada sin secretos

En una terminal propia fuera del sandbox, este contraste usa únicamente
variables explícitas no secretas y no ejecuta print, login ni modelos.
Ejecutarlo desde el mismo cwd para ambos casos. No enviar la salida JSON
original de `claude auth status`: puede contener identidades.

```sh
python3 - <<'PY'
import json, os, shutil, subprocess
exe = shutil.which('claude')
assert exe is not None and 'USER' in os.environ
base = {k: os.environ[k] for k in ('HOME', 'PATH', 'TMPDIR', 'LANG')
        if k in os.environ}
for label, env in [('minimal', base), ('minimal+USER', dict(base, USER=os.environ['USER']))]:
    r = subprocess.run([exe, 'auth', 'status', '--json'], env=env,
                       capture_output=True, text=True, timeout=10)
    try:
        data = json.loads(r.stdout)
    except ValueError:
        data = {}
    safe = {'context': label, 'exit': r.returncode,
            'stderr_present': bool(r.stderr)}
    if isinstance(data, dict):
        if isinstance(data.get('loggedIn'), bool):
            safe['loggedIn'] = data['loggedIn']
        for key, allowed in [('authMethod', {'none', 'claude.ai', 'oauth_token',
                                            'api_key', 'api_key_helper', 'third_party'}),
                             ('apiProvider', {'firstParty', 'bedrock', 'vertex', 'foundry'})]:
            if key in data:
                safe[key] = data[key] if data[key] in allowed else 'other'
    print(json.dumps(safe))
PY
```

No universalizar el resultado a otra versión, cuenta, plataforma o sesión.
La configuración local se comprobó antes para descartar un helper declarado;
no ejecutar helpers ni incluir credenciales al reproducir el diagnóstico.
Si otra sesión no reconoce auth incluso con USER, el usuario deberá comprobar
su contexto con status filtrado antes de considerar un login en su terminal.
No se requiere esa intervención en el estado observado hoy.
