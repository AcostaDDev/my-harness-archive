## Cambio y límite resuelto

`cli-1` generaba `model_providers.openai.request_max_retries=0` y
`model_providers.openai.stream_max_retries=0`. El primer smoke real mostró que
Codex 0.162.1 rechaza la definición por ID integrado reservado.

La [referencia oficial](https://learn.chatgpt.com/docs/config-file/config-reference)
y su [esquema](https://learn.chatgpt.com/docs/config-schema.json) documentan los
controles de retries en proveedores personalizados. No se encontró una opción
admitida de cero para el integrado en las versiones fijadas. `cli-2` elimina
ambos overrides y conserva `model_provider="openai"`, auth propia de la CLI,
versiones/modelos/esfuerzos explícitos, sesión nueva y políticas previas.
No crea un proveedor personalizado ni cambia a una API de pago para controlar retries.

Capabilities y spec por intento registran `built-in-defaults/unknown` para Codex.
El adaptador conserva una invocación por intento y no hace fallback/reintentos
propios; los retries internos de la CLI no se controlan ni miden en esta entrega.
Defaults publicados no equivalen a límites efectivos observados. D019.

La versión del adaptador sube a `cli-2`, vinculada al job congelado y a la spec.
La comparación previa a efectos bloquea jobs antiguos `cli-1`, incluso con la
misma configuración externa. No reescribe snapshots/resultados ni cambia esquema
0005 o codec; no añade autoarranque ni entradas API/CLI/UI gestionadas.
