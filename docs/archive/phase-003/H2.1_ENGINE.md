# H2.1 — Extracción aislada del motor

## Frontera fijada antes del traslado

`ProjectContext` contiene raíz canónica de checkout, rutas documentales relativas,
perfil y política efectiva. No deriva rutas de la instalación del paquete. El
núcleo usa únicamente biblioteca estándar y puertos explícitos para agentes,
comandos y captura de evidencia. No importa FastAPI, SQLite ni perfiles concretos.

Se extraen planificación, evidencia/política de archivos, validación, revisión,
aceptación y coordinación síncrona. El historial de esta extracción es un valor
inmutable en memoria, pasado explícitamente al revalidar/reintentar; no sustituye
la autoridad SQLite futura. No hay entrada CLI/HTTP, proceso de agente, escritor
Git, restauración de archivos, actualización de documentos ni supervisor.

El perfil ReferenceProject declara preparación, baseline Django/Docker/PostgreSQL,
formato y restricciones de ese proyecto. Esas declaraciones no se ejecutan en
esta entrega; las pruebas usan adaptadores falsos y repositorios desechables.

El flujo heredado se caracteriza desde las funciones del inventario H0.1:
`next_task_id`, `deterministic_task`, `plan_task`, `run_validations`,
`review_task`, `stalled_review_signature`, `validate_and_review_task`,
`revision_attempts`, `execute_iteration` y `resume_task`. La aceptación extraída
es una decisión sobre evidencia, nunca un commit. H2.4 añadirá captura Git real,
worktrees, preparación exacta del commit y recuperación idempotente.

Se conserva el presupuesto de correcciones incluso al reintentar y al revalidar.
Cada llamada tiene identidad nueva, sin identificador de conversación reutilizable;
errores/parciales se conservan y detienen el flujo. La planificación `auto` solo
usa el planificador cuando el contrato documental está incompleto, nunca tras
un error de proveedor. Concesiones de alcance requieren intervención explícita;
no se trasladan restauraciones automáticas ni ampliaciones silenciosas de contrato.
Esto aplica las invariantes aceptadas de preservar cambios y congelar contratos.

Entrega: 2026-10-11. [Alcance original](NEXT_STEPS.md) conservado.

La referencia se leyó estáticamente, incluidos sus tests de workflow y planificación;
no se importó ni ejecutó. Funciones/ubicaciones y revisión están en el inventario
H0.1. Los tests nuevos son sintéticos y se escribieron en este repositorio.

Los modos de planificación son `auto`, `deterministic` y `agent` (el anterior
`codex`, renombrado para que el núcleo no dependa de un proveedor). Una selección
fuera de política no dispara planificación alternativa. El resultado
`acceptance_ready` solo indica elegibilidad offline: no es tarea gestionada
aceptada/completada, commit, migración de modo ni actualización de documentos.

`resume` recibe el historial y contexto originales. Revalidar no llama al
ejecutor; `retry_executor=True` lo llama en sesión nueva y consume una corrección.
El comportamiento legacy que reiniciaba automáticamente un BLOCKED sin cambios
queda sustituido por esta decisión explícita, conforme a la separación de
«Revalidar»/«Reintentar ejecución» de la especificación §8. Contrato/política
distintos exigen una operación futura de cambio de versión, no una reanudación
silenciosa. Ampliaciones de alcance se detienen como decisión pendiente.

## Criterios y evidencia de comprobación

- 48 casos nuevos en `tests/product/test_engine.py`, con repositorios creados
  mediante `git init` en directorios temporales. Planificación completa/incompleta,
  identidades, selecciones y prompts congelados; contextos y rutas independientes.
- Sesiones nuevas por planificación/ejecución/review/corrección, sin reutilizar
  conversación; selección explícita de la review para la siguiente corrección.
  Historial anterior inmutable, paradas acumuladas y presupuesto conservado al
  revalidar/reintentar, incluyendo intentos fallidos y límite cero.
- Errores de agente/entorno/comando, JSON inválido/no finito, terminal ausente y
  exit distinto de cero o inválido no crean llamadas ocultas. Review malformada
  y su intento se conservan; se puede revalidar sin replantear.
- Ciclo sin cambios y hallazgos/validaciones repetidos se detiene; cambios en la
  validación permiten continuar. Denegaciones necesarias sin progreso detienen;
  denegación incidental no sustituye el juicio ACCEPT. BLOCKED conserva preguntas;
  stops operativos no contienen un veredicto de review.
- ACCEPT con tests fallidos, timeout, política incumplida, preguntas/concesiones
  pendientes o huella modificada queda inelegible. Cambio durante validación
  detiene antes de review. No se restauran archivos ni se borra evidencia.
- Comandos estructurados, orden/deduplicación, vacíos, duración ausente y rechazo
  de comandos no permitidos. Los prefijos no acreditan confianza en código ni
  autorizan ejecución real. Preparación y baseline ReferenceProject recorridos con
  runner falso; ningún comando de ese stack se ejecutó.
- Regresión completa: 128 pruebas pytest y 121 subtests; los 12 checks ligeros
  de biblioteca estándar, importación del núcleo con `python -S`, frontera de
  imports recursiva, contratos OpenAPI y migraciones ida/vuelta/check correctos.
- `npm --prefix frontend run check` y `npm --prefix frontend run build` correctos.
  API, CLI, almacenamiento y frontend conservan sus contratos; no se necesitan
  regeneración ni nueva migración. Diff y whitespace revisados antes del commit.

## Límites de esta entrega

Historial/snapshots en memoria, sin durabilidad, cola, exclusión, cancelación ni
recuperación tras reiniciar un servicio. Solo adaptadores falsos: `fresh_session`
expresa el contrato del puerto, no acredita comportamiento de una CLI real.
Los resultados no infieren uso, cuota, modelo observado ni duración ausentes.

`SyntheticWorkspace` calcula huellas de una lista de archivos de fixture y una
base sintética. No descubre cambios Git, no lee staged/untracked automáticamente,
no captura un snapshot atómico ni certifica un commit. Las pruebas que añaden un
archivo incluyen su ruta expresamente. H2.4 resolverá el adaptador completo.

El formatter del perfil es una declaración, no un paso mutador activo. Las rutas
del helper ReferenceProject son referencias heredadas, no un helper instalado en cada
checkout. Preparación/formato/helpers reales necesitan adaptadores y autorización
de confianza posteriores; importar el perfil no los ejecuta. Tampoco se porta
cierre/reconciliación de fase, permisos interactivos, grants automáticos ni lotes.

Sin proveedores/red, agentes, harness en desarrollo, servidores/navegador nuevos,
runs reales, instalaciones/tests en ReferenceProject ni cambios globales. Se mantiene
el aviso conocido HTTPX/Starlette y uv ignora el entorno externo. H2.2 queda
pendiente; no se inició en esta entrega.
