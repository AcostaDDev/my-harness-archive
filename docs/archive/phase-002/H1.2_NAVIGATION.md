Completado el 2026-10-11. [Criterios originales](NEXT_STEPS.md),
[formatos legacy](../phase-001/LEGACY_FORMATS.md) y decisión D013.

## Recorrido y autoridad

La UI abre «Proyectos importados»: proyecto/origen → fase → tarea → run observado
→ artefacto. Cada directorio de run mantiene su identidad y ruta. Las tareas se
agrupan por identidad del directorio sin colapsar runs distintos, y task.json
conserva sus identidades/contrato como campos observados. Las fases muestran
procedencia del nombre de directorio, archivo de fase y campos JSON declarados,
incluida la siguiente fase propuesta, con una ruta de muestra por tipo de origen.
Los documentos STATE/NEXT_STEPS/ROADMAP y archivo de fases se pueden leer desde
el proyecto; no se infieren tareas ejecutadas a partir de encabezados documentales.

La timeline es un índice paginado de archivos, ordenado por ruta/índice explícitos;
no una cronología inventada de invocaciones. Desde un artefacto se consultan campos,
hallazgos, resultados de criterio, preguntas y comandos paginados. Cada entrada
conserva su JSON pointer y el path/SHA-256 de la observación. Stops operativos y
reviews se mantienen separados. Los archivos pendientes/ausentes/erróneos siguen
visibles; la review parcial puede leerse como texto truncado sin asignarle veredicto.

Solicitudes, selecciones de contrato y modelos reportados se muestran con su origen.
Ausencia, null explícito y cero reportado permanecen distintos. La duración es del
comando o del resultado reportado, nunca de un test inferido. Tokens/model usage
son datos reportados; no se agregan wrappers duplicados. Coste equivalente API
no es factura ni porcentaje de cuota. ACCEPT/READY no certifican commit/cierre.

Las simulaciones H0.3 continúan disponibles en una pestaña separada. H1.1 sigue
siendo la única entrada de importación, mediante CLI; las consultas no reimportan.

## Contratos HTTP y límites

Todos bajo `/api/legacy`, con esquemas Pydantic y OpenAPI/tipos generados:

| GET | Contenido |
|---|---|
| `/projects` | Raíces importadas y fecha de última observación |
| `/projects/{id}/phases` | Identidades de fase y muestras de procedencia |
| `/projects/{id}/tasks?phase=…` | Identidades de tarea del directorio |
| `/projects/{id}/runs?phase=…&task=…` | Runs observados, sin estados gestionados |
| `/projects/{id}/artifacts?run_id=…` | Metadatos/timeline de ese run; sin filtro, documentos del proyecto |
| `/projects/{id}/artifacts/{id}/entries` | Campos, comandos, findings/preguntas del payload indexado |
| `/projects/{id}/artifacts/{id}/content` | Tramo de texto verificado contra SHA-256/tamaño indexados |

Listas/entradas: `offset` no negativo y representable con precisión en JavaScript,
`limit` 1–100 (UI 20); `next_offset` explícito o null. Valores estructurados con
más de 16 384 caracteres JSON serializados quedan `truncated`, conservando
procedencia y acceso al original. Los listados de artefactos y la lectura de bytes
no cargan payloads JSON/JSONL del índice. Las proyecciones estructuradas cargan el
JSON de un artefacto como unidad y paginan sus entradas.

Contenido: cursor en bytes; `limit` 4–16 384 (UI 8192), hasta tres bytes adicionales
para completar UTF-8. Cada petición abre ruta/raíz por componentes sin seguir
enlaces, rechaza archivos no regulares, calcula el hash por bloques y solo conserva
el tramo solicitado. Verificación máxima 64 MiB; fichero mayor queda `too_large`.
Hash/tamaño distinto o cambio durante lectura queda `changed`, origen desaparecido
`missing`, sin hash indexado `unindexed`, ruta/enlace/no regular `unsafe`, denegación
`unreadable` y bytes/cursor inválidos `invalid_utf8`. Solo `verified` sirve texto;
incluso en JSON parcial significa igualdad de bytes, no validez de revisión.
Rutas/IDs no indexados devuelven 404 y parámetros fuera de límites 422.

La UI usa texto escapado por React, nunca HTML/comandos/prompt ejecutables.
Identifica por separado el payload indexado y los bytes verificados, y avisa si
una reimportación cambió el hash desde que se abrió la lista. No hay copia de
cuerpos nuevos, cache, watcher, SSE ni relectura automática del índice.

## Verificación

- 59 pruebas pytest y 121 subtests, 19 casos nuevos de navegación/contenido; los
  12 checks ligeros de biblioteca estándar también pasan. Núcleo con `python -S`,
  frontera de imports, migración H1.1 y persistencia/simulaciones H0.3 conservadas.
- Cinco escenarios completos por HTTP, con paginación pequeña para cruzar límites,
  hashes/bytes/mtime sin modificación. REVISE/ACCEPT en la misma historia, preguntas,
  stop, request/telemetría, ausencia/null/cero, duración por comando, resultados
  ausentes y review parcial. P900/P901 y archivo documental de cierre accesibles.
- Logs/diffs UTF-8 de 60 000 bytes reconstruidos por tramos, archivo vacío, errores
  locales, rutas desconocidas, límites y truncamiento. Cambios antes/durante lectura,
  desaparición, enlaces de archivo/directorio/raíz y FIFO no sirven bytes nuevos.
- OpenAPI y tipos regenerados; prueba de igualdad con runtime, TypeScript y build
  Vite correctos. Alembic upgrade/check/downgrade/upgrade cubiertos por regresión;
  no hay cambios de esquema en H1.2 (`0002_legacy_index`).
- UI compilada en Chrome sobre copias sintéticas y SQLite local ignoradas: cinco
  escenarios, historial, hallazgos/preguntas, parcial, consumo/duración, archivo
  documental, paginación de artefactos y log UTF-8 de 34 500 bytes. Modificar esa
  copia muestra `changed` y no devuelve texto nuevo. Captura inspeccionada.
  Simulación H0.3 creada correctamente; Uvicorn detenido al finalizar.

Comandos de checks en README/AGENTS, ejecutados con locks y sin red externa.
Persiste el aviso de Starlette sobre HTTPX 0.28.1, sin modificar el baseline.
Sin proveedores, agentes, harness, runs reales ni acceso/configuración de ReferenceProject.
No se probaron otros sistemas, carga, cuota o snapshots entre archivos/escritores
concurrentes. El hash requiere releer cada archivo por tramo; los límites evitan
lecturas/cuerpos ilimitados pero no acreditan rendimiento a escala. H1.3 no iniciado.
