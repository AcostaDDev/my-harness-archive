## Solicitudes y autoridad

`permission_requests`, migración `0009_permissions`, conserva la solicitud,
SHA-256, versión, caducidad UTC, decisión y consumo. Cinco categorías independientes:
`files`, `tools`, `network`, `product`, `acceptance`. Cada solicitud identifica
operación, alcance exacto, solicitante declarado, intento de procedencia y motivo.
La huella incluye esos campos, contexto/contrato/versiones congelados y vigencia.
Las operaciones son `write`, `use`, `connect`, `decide`, `accept` respectivamente;
los argumentos adicionales se rechazan: una regla como `Bash(test-runner check)`
contiene su alcance completo y no admite argumentos implícitos del cliente.

La configuración confiable del servidor puede aportar `ManagedProject.permission_authority`:
cuatro mapas `global`, `project`, `contract`, `provider`, con listas de objetivos
exactos por categoría. Se congelan como JSON en `versions.permission_authority`
al crear el run; para uso de biblioteca se proporciona esa misma versión explícita.
Ausencia en cualquiera de los cuatro mapas deniega la concesión. Los cambios de
configuración no amplían runs existentes. No hay editor de políticas persistentes.

Ejemplo sintético de autoridad (no activa CLI):

```python
authority = {
    layer: {"tools": ["Bash(test-runner check)"]}
    for layer in ("global", "project", "contract", "provider")
}
project = ManagedProject("synthetic", context, versions,
                         permission_authority=authority)
```

Los ficheros además deben caber en el contrato congelado y las restricciones del
perfil: rutas protegidas, sensibles, symlinks y escapes no pueden concederse por
esta vía. La concesión no amplía `allowed_paths`, no modifica requisitos ni borra
cambios. Producto y aceptación/cierre conservan auditoría separada; no resuelven
preguntas, alteran contratos, crean ACCEPT ni autorizan commits automáticamente.
El commit sigue exigiendo la acción propia y evidencia exacta H2.4.

## Transacciones, vigencia y recuperación

La petición y la decisión exigen versión observada del run; la segunda exige
además versión de solicitud y huella. Solo se permite editar en una frontera
STOPPED/BLOCKED/REVISION_LIMIT/INTERRUPTED, sin jobs pendientes del checkout.
No se puede autorizar una llamada viva ni una ejecución ya encolada. Una nueva
petición para el mismo objetivo vigente debe sustituir la anterior explícitamente.
Sustituir crea otro UUID y marca SUPERSEDED, conservando la decisión anterior.
Una solicitud caducada, alterada, sustituida o ya decidida rechaza la autorización.
Las lecturas proyectan EXPIRED sin reescribir históricos.

Conceder/denegar registra UID y nombre del usuario local del **servicio**, fecha,
motivo, huella, caducidad y alcance `once` o `task`. El solicitante es declarado;
esta identidad no autentica al humano del navegador. La sesión local permanece
pendiente como en D028/D029; no se introduce una credencial ficticia ni se atribuye
identidad a un campo libre.

Antes de cada intento, la transacción del journal resuelve las concesiones y
conserva un snapshot con hash, identidad del intento, contexto/contrato y filas
exactas. Solo el ejecutor recibe permisos operativos. `once` se consume con la
intención, incluso ante caída o rechazo antes de lanzar el proceso; `task` puede
aplicarse a intentos posteriores de ese run hasta caducidad o sustitución.
Una denegación operativa vigente bloquea el intento antes del adaptador (con
historial y presupuesto conservados); `once` también se registra como consumida.
Reintentar tras una caída requiere conciliación H2 y una acción explícita; no
restaura una concesión consumida. Codec 5 conserva estos snapshots y lee formatos
1–4 sin inventar datos ni reescribir las filas de intentos históricos.

Revalidar ejecuta preparación declarada, validaciones y revisión, preservando la
implementación y sin ejecutar el agente implementador. Una review REVISE detiene
la acción y solicita reintento explícito; no consume concesiones del ejecutor.
Reintentar ejecutor crea un intento nuevo y conserva el presupuesto acumulado.
El límite agotado continúa visible y no se repone al conceder permisos. El servidor
proyecta acciones habilitadas; la UI consume esa proyección y las mutaciones siguen
validándose transaccionalmente. Conceder/denegar no crea jobs ni dispara el supervisor.

## CLI, API y UI

Adaptador `cli-4`: `CLIConfig.grantable_tools` declara reglas concedibles y forma
parte del hash congelado. Para herramientas gestionadas por estas reglas, el
inventario CLI permanece cerrado hasta una regla de baseline explícita o una
concesión persistida para este intento. La regla exacta se añade a `--allowedTools`
de Claude sin mutar la configuración ni una llamada viva. Se conservan dontAsk,
sesiones nuevas, MCP vacío, settings/hooks aislados y ausencia de fallback.
Se comprueba vigencia otra vez al construir argv. Configuraciones cli-3 antiguas
no se ejecutan bajo cli-4 silenciosamente.

Una concesión de ficheros no añade herramientas. La CLI no admite aislamiento por
dominio de red: rechaza una concesión de red antes del lanzamiento. Las reglas
CLI y el control posterior del diff no son sandbox físico; shell puede tener
efectos externos. La autoridad del servidor debe declarar solo capacidades reales.
Esta entrega caracteriza el transporte con procesos independientes sintéticos;
no certifica la aplicación interna de reglas por las CLI instaladas.

Rutas bajo la guardia Host/Origin/`X-Harness-Local` gestionada:

- `GET /api/managed/runs/{run_id}/permissions`: histórico y estado efectivo.
- `POST /api/managed/runs/{run_id}/permissions`: petición o sustitución.
- `POST /api/managed/runs/{run_id}/permissions/{id}/decision`: conceder/denegar,
  con motivo, versiones, huella y `confirmed=true`.

La UI muestra las cinco categorías, alcance exacto, vigencia, motivo, huella,
solicitante, procedencia y auditoría. Incluye sustitución, una vez/esta tarea y
confirmación que se limpia al cambiar la versión. Los conflictos conservan su
código/diagnóstico; no sustituyen versiones ni repiten mutaciones automáticamente.
Los intentos muestran el snapshot de permisos ya persistido. OpenAPI y tipos
regenerados desde Pydantic.
