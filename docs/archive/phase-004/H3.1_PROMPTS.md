Modelos concretos y Django/Docker no entran en plantillas base. La política del
contexto aporta las selecciones, y `ProjectProfile.executor_instructions` aporta
instrucciones específicas. D015 sigue prevaleciendo sobre concesiones y restores
legacy: un prompt nunca modifica las guardias del motor.

Resolución por reemplazo completo: recurso base → activación global `core` →
activación `profile` por nombre de perfil → activación `project` por raíz canónica.
Los ámbitos compartidos se identifican y advierten en el editor. Un proyecto no
puede consultar ni copiar versiones privadas de otra raíz. No se leen archivos
arbitrarios del checkout para resolver overrides; SQLite es su autoridad.

## Persistencia y concurrencia

Migración explícita `0008_prompt_versions`: `prompt_versions` (solo inserciones
desde el servicio), `prompt_heads` (generación y puntero activo) y
`prompt_activations` (versión anterior/nueva, motivo y fecha UTC).
Cada guardado crea UUID/hash/procedencia nuevos. La activación cambia únicamente
el puntero y añade auditoría; ninguna operación modifica una versión histórica.
Rollback copia una versión accesible a otro UUID borrador y exige activación
separada. Una versión guardada que no sea la activa es seleccionable; la auditoría
distingue las versiones antiguamente activas de borradores nunca activados.

Las mutaciones exigen `expected_version` de la generación del ámbito/nombre.
La primera escritura serializa SQLite y un compare-and-swap hace que solo una
acción concurrente gane; 409 obliga a recargar explícitamente. Borrador inválido,
conflicto y activación de ámbito ajeno no dejan generación ni auditoría parcial.
La lectura del catálogo completo usa una única transacción de lectura.

## Congelación antes de efectos

El núcleo solo depende de biblioteca estándar e inyecta un resolvedor; el
supervisor usa el repositorio SQLite. Antes de preparación se valida el catálogo
completo. Antes de cada invocación se vuelve a resolver, validar y renderizar, y
`agent_started` persiste la petición antes de llamar al adaptador. Una activación
concurrente afecta a una resolución posterior, nunca a la petición ya creada.

Sintaxis `{{UPPERCASE_NAME}}`, lista fija y obligatoria por nombre, máximo 100000
caracteres. Variables desconocidas, omitidas o mal formadas y hashes discrepantes
se rechazan. Renderizado de una sola pasada: llaves contenidas en datos no se
interpretan como variables adicionales. El editor no modifica esquemas ni concede
herramientas, permisos o selecciones fuera de política.

Cada intento conserva plantilla/ID/ámbito/propietario/procedencia/hash, variables
con valores, instrucciones de routing cuando proceden, esquema de salida fijo y
su hash, referencias STATE/NEXT_STEPS, texto renderizado y hash. Las referencias
del contrato también quedan en TASK_JSON o INPUT_JSON y el contrato congelado.
El adaptador CLI `cli-3` mantiene su envoltorio de transporte (shape/política)
y captura el texto finalmente transmitido y su hash por el protocolo H2.3;
`rendered` identifica el texto del motor, no sustituye esa captura del transporte.
No se cambió argv, autenticación, herramientas ni versión del adaptador.

Codec 4 para catálogos/snapshots nuevos. Los formatos 1–3 se siguen leyendo sin
atribuirles una versión histórica desconocida. Comparar requests restaurados
permite campos opcionales ausentes, conservando los bytes de filas antiguas.
El último catálogo resuelto también queda en el historial del run para reanudar
con esas versiones tras una parada o caída. No hay aplicación de activaciones
nuevas a runs detenidos en esta entrega. Los anteriores a H3.1, sin catálogo,
resuelven uno al preparar la nueva acción; sus intentos anteriores siguen sin
metadatos de prompt inferidos.

## API y UI

Bajo `/api/managed/projects/{id}/prompts`:

- GET catálogo y `/{name}` con `scope=core|profile|project`.
- POST `/{name}/validate`: validación sin escrituras ni agentes.
- POST `/{name}/versions`: template o `from_version`, exclusivamente.
- GET `/{name}/diff?before=…&after=…`: diff textual entre versiones accesibles.
- POST `/{name}/activate`: generación, ID guardado, motivo y `confirmed=true`.

Los errores siguen `{code, diagnostic}` y las guardias Host/Origin/CSRF existentes.
Pydantic/OpenAPI generan los tipos React. El editor ofrece ámbito, plantilla,
versiones/procedencia, variables, textarea, validación, guardado, diff, rollback,
confirmación y auditoría. No reenvía mutaciones automáticamente. Un error conserva
el texto; «Recargar versiones» actualiza la generación sin borrar la edición.
Cambiar contenido/selección/generación limpia la confirmación. Activar exige que
el texto mostrado coincida con la versión guardada seleccionada.
Los intentos exponen además `prompt` y `prompt_snapshot` en la vista de evidencias;
en históricos sin snapshot se devuelve null.
