# H5.4 — Diagnósticos locales de compatibilidad

Entrega offline del 2026-10-13. [Alcance original](NEXT_STEPS.md), D042.

## Uso explícito

`diagnose-cli` acepta un archivo JSON de datos de una sola `CLIConfig`. No carga
módulos de configuración gestionada, abre SQLite ni crea jobs. Ejemplo de forma
(reemplazar ruta y entorno por valores explícitos adecuados al ejecutable local):

```json
{
  "provider": "codex",
  "executable": ["/ruta/absoluta/al/codex"],
  "cli_version": "0.162.1",
  "environment": {},
  "timeout_seconds": 60,
  "tools": [],
  "allowed_tools": [],
  "grantable_tools": []
}
```

```sh
UV_CACHE_DIR=.local/uv-cache uv run --frozen --offline python -m harness_local.cli diagnose-cli /ruta/diagnostico.json
```

El comando se ha verificado solo con configuraciones y ejecutables sintéticos.
Para Claude: `provider: "claude"`, baseline `2.1.295` y su ejecutable explícito.
Las versiones Codex admitidas siguen siendo `0.161.0` y `0.162.1`. Una versión
nueva exige caracterización y cambio deliberado del baseline; no se sustituye
la esperada por la detectada. La salida enumera los baselines vigentes del código.

El archivo tiene los campos obligatorios `provider`, `executable` (argv de prefijo),
`cli_version`, `environment` (objeto completo, sin herencia) y `timeout_seconds`.
Los tres campos de tools son opcionales. Se rechazan claves desconocidas o
repetidas, tipos incorrectos y configuraciones rechazadas por `CLIConfig`.
Máximo 64 KiB, UTF-8, archivo regular; se rechazan enlaces finales simbólicos,
enlaces duros y FIFO. No pasar un archivo de credenciales como configuración.
La biblioteca ofrece `diagnose(config)` para una `CLIConfig` ya construida.

El entorno vacío del ejemplo es deliberadamente explícito, no una configuración
recomendada de ejecución. HOME/PATH/USER/TMPDIR y herramientas se suministran en
la configuración que se quiera examinar; sus valores nunca se imprimen. La
validación es estructural: no comprueba que HOME/USER permitan autenticar, ni lee
configuraciones globales para intentar repararlas. D024 sigue fijando la
validación de USER del constructor del smoke, sin modificarlo aquí.

## Comprobaciones y resultados

Comparte `preflight_config` con `CLIProcessAdapter.preflight()`:

1. Ejecuta únicamente `--version` con stdin cerrado, entorno explícito y cwd
   temporal ajeno al checkout. Solo acepta la línea completa reconocida de la
   CLI, sin banners adicionales, sufijos de versión o bytes UTF-8 inválidos.
2. Si coincide exactamente con la versión solicitada, ejecuta `exec --help`
   (Codex) o `--help` (Claude) y verifica los tokens de flags del preflight
   existente. `--model-extra` no satisface `--model`.
3. Ante fallo de una sonda, no ejecuta la siguiente para ese proveedor. No hay
   fallback, reintento, login/status, prompt de inferencia ni corrección automática.

JSON formato 1; exit 0 solo con `version_help_match`, exit 1 ante diagnóstico
negativo o configuración inválida. Errores de sintaxis de argparse mantienen
exit 2. El informe separa versión solicitada y observada, capacidades requeridas,
flags ausentes (null si no se llegó a comprobar), códigos de salida y diagnósticos
con un paso de corrección concreto. `unknown` nunca equivale a compatible;
`incompatible` indica versión distinta o flags ausentes.

Cada sonda tiene un máximo de 10 segundos y 256 KiB combinados stdout/stderr.
El timeout de ejecución declarado en CLIConfig no amplía el del diagnóstico.
Se drenan ambos pipes incrementalmente y se termina el grupo POSIX creado para
la sonda incluso cuando el líder sale dejando un hijo con el pipe abierto.
Se cierran descriptores y se espera al líder hasta un segundo adicional. Un fallo
de limpieza impide certificar éxito y exige comprobar manualmente su parada;
no se señalizan procesos históricos.
La limpieza del directorio temporal no toca archivos del checkout.

No se exponen stdout/stderr libres, valores del entorno, argv/rutas ni textos de
excepciones. Solo se conserva la línea de versión estrictamente reconocida y el
hash SHA-256 del help completo válido. Errores inesperados, salida excesiva,
fallo de ejecución, salida no cero y timeout se convierten en códigos acotados.

## Límites e integración

`available` se conserva por compatibilidad con el consumidor existente, y solo
significa coincidencia versión/help. `not_checked` declara autenticación, cuota,
acceso al modelo, argv completo, permisos efectivos, aislamiento de red y retries
internos como no comprobados. Los fallos reales D018/D020 demuestran por qué help
no certifica semántica de configuración. Tampoco se prueba disponibilidad del
servicio remoto ni de dependencias de un perfil de proyecto.

No hay sandbox nuevo: solo usar ejecutables locales de confianza. Un wrapper o
binario malicioso puede ignorar `--help`/`--version`, acceder a ubicaciones que el
SO permita o escapar del grupo. No se promete aislamiento físico ni control de
sus efectos internos. El diagnóstico no solicita operaciones de red o consumo.

El adaptador conserva `cli-4`: mismo argv de inferencia, capacidades, permisos y
hash de configuración. Cambia únicamente el preflight de lectura, con resultado
aditivo y rechazo más estricto. No reescribe snapshots, jobs, historial ni reportes
antiguos. No hay migración, codec nuevo, dependencias, API/UI ni arranque automático.
La API no acepta rutas/ejecutables para lanzar este diagnóstico.

## Verificación

Pruebas sintéticas de ambas CLI, versión distinta/desconocida, flags parciales,
UTF-8 y salida inesperada, timeout, pipes cerrados y heredados por hijos, errores,
flood stdout/stderr, JSON inválido/profundo/duplicado, rutas especiales, entorno
sin herencia ni filtrado de secretos, CLI/exit codes y snapshots intactos.
Regresión de adaptadores/procesos/entorno del smoke y suite completa documentadas
en [STATE](STATE.md). No se ejecutaron CLI reales, auth status, proveedores,
smokes, instalaciones ni cambios globales. H5.5 queda sin iniciar.
