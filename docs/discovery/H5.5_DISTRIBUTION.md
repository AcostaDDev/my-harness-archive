# H5.5 — Assets empaquetados y entrada local

Entrega del 2026-10-13, D043. [Alcance original](H5.5_SCOPE.md).

## Construcción reproducible

Baseline comprobado: macOS ARM64, Python 3.14.4, uv 0.12.19,
Node 24.15.0, npm 11.12.1; dependencias y backend uv_build fijados en
`pyproject.toml`, `uv.lock` y `frontend/package-lock.json`. Preparación inicial
según README; las primeras descargas necesitan red. Con las cachés disponibles:

```sh
UV_CACHE_DIR=.local/uv-cache uv run --frozen --offline python scripts/build_distribution.py
```

El script comprueba versiones de herramientas, hace npm ci offline desde lock,
tipos y build Vite; copia el paquete y los assets a un staging temporal y construye
sdist y wheel desde ese sdist. Exporta dependencias transitivas de producción con
pins y hashes de uv.lock a `dist/requirements.txt`. No cambia versiones ni publica.
Los assets generados no se versionan en Git. No usar `uv build` directamente sobre
el checkout para distribuir: esa construcción de desarrollo no incluye la UI.

Salida: `dist/harness_local-0.1.0-py3-none-any.whl`,
`dist/harness_local-0.1.0.tar.gz`, `dist/requirements.txt`. El sdist incluye assets
precompilados y permite reconstruir el wheel sin Node. No se promete identidad
binaria entre builds (timestamps de archivos), sí dependencias fijadas y bytes de
recursos contrastados con el build. La versión del paquete sigue siendo 0.1.0.

## Instalación aislada y arranque

Copiar wheel y requirements a una carpeta local. Elegir un venv nuevo y una ruta
SQLite absoluta fuera de los proyectos gestionados. Desde cualquier directorio,
con Python 3.14.4 y uv 0.12.19 instalados:

```sh
uv venv --python 3.14.4 --no-python-downloads /ruta/nueva/venv
uv pip sync --python /ruta/nueva/venv/bin/python --require-hashes /ruta/paquete/requirements.txt
uv pip install --python /ruta/nueva/venv/bin/python --no-deps /ruta/paquete/harness_local-0.1.0-py3-none-any.whl
/ruta/nueva/venv/bin/harness-local init-db --database /ruta/datos/nueva.sqlite3
/ruta/nueva/venv/bin/harness-local serve --database /ruta/datos/nueva.sqlite3
```

Añadir `--offline` a los tres comandos uv si sus dependencias están en caché;
el verificador de esta entrega lo hace. No se requiere instalación global del
producto ni Node para servir. Abrir `http://127.0.0.1:8013`; `--port` permite otro
puerto válido. Ctrl+C detiene el proceso. Un solo worker, loopback IPv4 fijo,
sin reload, proxy headers ni apertura automática del navegador.

`init-db` reclama exclusivamente un archivo nuevo y ejecuta las migraciones
empaquetadas. Rechaza destinos existentes y auxiliares WAL/SHM/journal huérfanos;
fallos dejan el parcial para inspección. Nunca repara, borra, reutiliza ni migra
bases existentes. `serve` exige base preparada y assets, y diagnostica ausencia,
esquema incompatible y puerto inválido. El lifespan comprueba configuración y
archivos restaurados antes de servir; un error termina con estado no cero.

`--database` es obligatorio, absoluto e independiente de `HARNESS_DATABASE_URL`.
Las entradas CLI anteriores conservan su configuración. Migraciones canónicas en
`src/harness_local/migrations`; alembic.ini apunta allí para desarrollo. Una
actualización de una base existente exige servicio/escritores detenidos, backup
previo y migración explícita con una versión compatible; esta entrega no ofrece
un actualizador instalado ni downgrade automático.

`HARNESS_MANAGED_CONFIG=módulo:atributo` conserva el opt-in existente. El módulo
Python de confianza debe estar instalado en el mismo venv; no se empaquetan demos,
configuraciones privadas, credenciales ni proyectos. Sin configuración: sin
proyectos/puertos/supervisor. La observación solo lee orígenes activados
explícitamente en SQLite. No invoca CLI/version/help ni proveedores al arrancar.
Las restauraciones ignoran incluso una configuración ambiental inválida, verifican
su bundle y permanecen en consulta. Guardias HTTP existentes conservadas.

## Verificación y límites

```sh
UV_CACHE_DIR=.local/uv-cache uv run --frozen --offline pytest -q tests/product/test_launcher.py
UV_CACHE_DIR=.local/uv-cache uv run --frozen --offline python scripts/check_distribution.py
```

El segundo comando necesita permiso para escuchar en loopback. Crea venv limpio,
instala offline pins con hashes y wheel sin dependencias adicionales, contrasta
bytes de código/plantillas/migraciones/assets, y ejecuta desde otra carpeta con
PATH limitado al venv, sin Node, PYTHONPATH ni configuración heredada. Comprueba
HTML/JS/CSS, health, API desconocida 404, guardia de mutación, simulación sintética,
reinicio, errores de configuración/esquema, backup y restauración de consulta con
mutación 409. Detiene sus procesos y retira solo su carpeta temporal.

Sin proveedores, datos privados, SQLite de trabajo, publicación, instalación
global ni cambios de configuración del usuario. Verificación HTTP real, sin
recorrido visual del navegador ni flujo gestionado con CLI real. La sesión local,
protección de lecturas H0/H1 y E2E amplios siguen pendientes. H5.6 no iniciado.
