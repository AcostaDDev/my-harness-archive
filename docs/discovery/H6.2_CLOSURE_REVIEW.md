## 3. Idempotencia, confirmaciones y carga por recurso

### Idempotencia y confirmaciones

- Repaso de `/api/managed`. Las mutaciones que encolan trabajo (runs y sus acciones, bootstrap, mensajes de chat y de
  planificación, aceptaciones, exportación, edición de documentos, transición, lote y reconciliación con agente) llevan
  `Idempotency-Key`. Las demás llevan versión esperada o hash de una vista previa (registro, activación, preguntas,
  autorizaciones, propuestas, borradores con CAS y prompts). El cliente reenvía solo envíos con clave (envío pendiente
  de H2).
- Reintentos en vivo, con la sesión del navegador, tras el recorrido: repetir el commit del run (con clave nueva y con
  la misma) → 409 «Run already has a recorded commit»; vista previa de otra transición desde P001 → 409; mensaje en la
  planificación de una fase ya transicionada → 409; vista previa de la aceptación de un proyecto ya creado → 409. La
  lista de runs no cambia.

### Carga por recurso

- El resumen del proyecto lee el proyecto, el modo, la lista de fases sin tareas y una página de 10 runs. Las tareas
  de la fase van en `…/phases/{code}/tasks` paginado.
- Los eventos van por cursor (50), los intentos y los runs paginados (30), los casos JUnit paginados (50) y las
  estadísticas paginadas. De los logs, la API solo expone metadatos de retención por flujo, sin contenido.
- **Hallazgo 1.** Los diffs no van paginados (ver Hallazgos).
- Siguen sin paginar listas pequeñas por diseño: fases (E1), conversaciones y jobs de un run.

### Markdown hostil

- Un único punto de HTML: `renderMarkdown` (`markdown-it` con `html: false`) en `MarkdownView`. Las respuestas del chat
  y el resto de textos se pintan como texto con React.
- 27 casos hostiles en `frontend/tests/markdown.test.mjs`, contrastados con una lista cerrada de etiquetas, atributos y
  destinos: `<script>`, `javascript:` con mayúsculas, entidades y tabuladores, `vbscript:`, `data:`, `on*=`, SVG con
  `onload` y `foreignObject`, Mermaid con HTML en etiquetas y `%%{init}%%` con `securityLevel: "loose"`, títulos, alt,
  referencias y bloques de código.
- En el navegador, el mismo contenido llegó por el flujo normal (propuesta del revisor → borrador → commit raíz) y se
  vio en la propuesta, en el visor de documentos y en oscuro y estrecho. `window.__pwned` siguió nulo, sin `<script>`
  ni atributos `on*` en el DOM renderizado, sin enlaces `javascript:`/`data:` y con la imagen externa bloqueada. Los

## Hallazgos

1. **Diffs sin paginar y sondeo continuo del run (medio).** `GET /runs/{id}` incluye el diff completo de cada ciclo
   (`CycleRead.diff`, hasta 4 MiB por ciclo según `MAX_DIFF_BYTES`). El número de ciclos crece con las revisiones y las
   revalidaciones, y `max_revision_cycles` no tiene techo superior. La página del run relee ese recurso cada 1,5 s junto
   con `/runs/{id}/jobs` (sin paginar) y la página de intentos, también cuando el run ya terminó. No hay error
   funcional, pero el criterio «diffs paginados» no se cumple y un run con varios ciclos grandes transfiere megabytes
   en cada sondeo. Corregirlo cambia el contrato de la API (una lectura del diff por ciclo y un resumen en el run) y el
   cliente, así que no es un defecto acotado de esta revisión. Se propone como tarea correctiva.
2. **Crear una conversación no es idempotente (bajo).** `POST /projects/{p}/conversations` (chat) y
   `POST /projects/{p}/planning` con `phase_planning` no llevan clave ni versión. Si se reintenta tras perder la
   respuesta, se crea otra conversación vacía. No ejecuta nada ni consume proveedores, y la UI no reenvía esas
   peticiones. La definición es única por proyecto (409). Una clave persistida requeriría una migración; se anota.
3. **Deriva en ámbar en una fase cerrada y transicionada (bajo, visual).** Tras la transición, P001 muestra en ámbar
   «Cambiados desde la base adoptada: NEXT_STEPS, ROADMAP, STATE». Esos documentos los cambió la propia transición y no
   hay nada que decidir en esa fase, mientras que el ámbar se reserva a lo que espera una decisión. También sigue
   habilitado «Previsualizar exportación» (`frontend/src/Phases.tsx:122`). Sin prueba de componente posible con el runner
   actual; se anota para la tarea correctiva.

Límites de las entregas que se conservan: un proyecto `typescript-web` recién creado no tiene `package.json` y el
ejecutor no puede crearlo (requiere una decisión aparte); las validaciones no guardan su hora (evolución por fase); dos
avisos *low* de KaTeX vía Mermaid; la planificación de una fase ya transicionada admite mensajes en la UI (el servidor
responde 409, comprobado); la guardia ante `Sec-Fetch-Site: cross-site` se mantiene (D079); borradores por pestaña;
ningún recorrido de H6.2 con CLI reales.
