## Perfil y aplicación de referencia

`harness_local.profiles.typescript_web.typescript_web_profile()` devuelve un
`ProjectProfile` inmutable. Importarlo no ejecuta procesos. Declara preparación,
comandos de validación, prefijos para comandos del contrato, rutas protegidas,
rutas sensibles e instrucciones del ejecutor. No concede herramientas, red,
decisiones de producto ni aceptación. Se selecciona explícitamente en el
`ProjectContext` del servidor, igual que ReferenceProject; el cliente no escoge un stack.

La [fixture](../../tests/fixtures/typescript_web/README.md) es una web estática
TypeScript con HTML, módulos ES y una calculadora de duración. Usa el compilador
TypeScript y el test runner de Node; no necesita React, Django, Docker, bundler,
backend ni servicio externo. Los scripts, tests, tsconfig y lock son baseline
protegido; cambiarlos requiere configurar otra política explícita en una tarea
apropiada, no una concesión que supere los techos existentes.

Matriz de perfiles comprobados:

| Perfil | Stack | Preparación y validación | Flujo gestionado |
|---|---|---|---|
| `reference_project` | Django/PostgreSQL/Docker | Declaraciones y fakes H2.1; stack real no ejecutado | No certificado con ese stack |
| `typescript-web` | Web TypeScript estática | Node/npm/tsc reales offline; tres tests y build | Git/SQLite reales temporales hasta COMMITTED; agentes falsos |

| Paso | argv del perfil | Resultado comprobado |
|---|---|---|
| Preparación | `node --version` | Node 24.15.0 |
| Preparación | `npm --version` | npm 11.12.1 |
| Preparación | `npm ci --offline --ignore-scripts --no-audit --no-fund` | Instala TypeScript 5.9.3 desde caché; lock y engines obligatorios |
| Validación | `npm run check` | `tsc --noEmit`, tipos estrictos |
| Validación | `npm run test` | Compila y ejecuta tres tests Node: cálculo, entradas inválidas e interacción |
| Validación | `npm run build` | Compila y genera `dist/index.html`, `main.js` y `estimate.js` |

Todos usan cwd `.` relativo al checkout. Versiones tienen timeout 30 s;
instalación y validaciones 120 s. La instalación declara
`npm_config_engine_strict=true`. El ejecutor del puerto recibe aparte su entorno
confiable y la caché explícita: el perfil no busca rutas del usuario ni ejecutables
desde la ubicación del motor. El lock propio fija integridad de TypeScript y no
modifica los locks uv/frontend. No se añaden dependencias Python.

La instalación es deliberadamente offline. Si falta la caché, se conserva el
fallo sin descargar ni reintentar. Población inicial de caché requiere una acción
de instalación con autorización de red independiente. Los comandos `npm run`
ejecutan scripts del repositorio confiable: `--ignore-scripts` solo evita scripts
de instalación, y los prefijos no son una frontera de seguridad.

## Uso y reproducción

Un proyecto con este perfil debe ofrecer los scripts y archivos de configuración
anteriores. La [fixture](../../tests/fixtures/typescript_web/) contiene el ejemplo
completo. La composición sigue siendo `ManagedProject(ProjectContext(...))` y
`ManagedConfig(ports_factory=..., commit_factory=...)`: agentes, `CommandRunner`
y evidencia por inyección, con versiones/configuración comprobadas por la factory.
No se añade registro HTTP, selector de perfiles ni supervisor automático.

Verificar con los puertos existentes, desde la raíz:

```sh
UV_CACHE_DIR=.local/uv-cache uv run --frozen --offline pytest -q tests/product/test_typescript_profile.py
```

También se pueden ejecutar los scripts directamente en una copia desechable,
sin modificar la fixture versionada:

```sh
web_example="$(mktemp -d /private/tmp/h43-web.XXXXXX)"
cp -R tests/fixtures/typescript_web/. "$web_example"
npm --prefix "$web_example" ci --offline --ignore-scripts --no-audit --no-fund --engine-strict --cache "$PWD/.local/npm-cache"
npm --prefix "$web_example" run check
npm --prefix "$web_example" run test
npm --prefix "$web_example" run build
```

La preparación y los scripts se verificaron mediante el runner del fixture. El test
configura HOME/TMPDIR temporales, PATH de Node/npm y configuración npm vacía de
usuario/global en archivos distintos. No hereda credenciales ni modifica la
configuración global. La caché existente se comparte; logs nuevos de npm quedan
en esa caché ignorada. Los builds/dependencias se excluyen por `.gitignore`.

## Evidencia y criterios de aceptación

16 casos nuevos bajo `tests/product/test_typescript_profile.py`:

- Preparación real, typecheck, tres tests Node y build; árbol/índice/HEAD intactos.
- Una regresión sintética → ejecutor falso que corrige `src/estimate.ts` →
  validaciones reales → review ACCEPT falsa → ACCEPTANCE_READY → commit H2.4
  exacto en un worktree. El checkout de origen conserva bytes y HEAD.
- Contexto/perfil/contrato/versiones congelados, prompts y snapshots de permisos,
  codec vigente y eventos de inicio/fin de seis comandos. Resultados preservan
  stdout, stderr, código de salida y duración; validación/review/aceptación quedan
  vinculadas a la misma evidencia Git. Lectura desde otro repositorio SQLite
  conserva el historial y resultado; no invoca agentes adicionales.
- ACCEPT no supera tests fallidos, error de tipos, build fallido o tests protegidos
  editados. La edición protegida se rechaza incluso con todas las validaciones
  correctas. No se admite el commit de esas aceptaciones fallidas.
- Cambio externo después de validar impide el commit antes de crear intención y
  conserva los bytes externos.
- Caché vacía, engines incompatibles o lock inconsistente detienen la preparación
  antes del agente; no se reparan manifiestos ni se descarga una versión distinta.
- Una denegación H3.2 `once` bloquea el siguiente intento explícito, mantiene el
  contrato y se registra consumida; los prefijos npm no la sustituyen.
- Comandos de contrato fuera de los prefijos declarados se rechazan sin procesos.
  Ambos perfiles son declarativos y el núcleo no incorpora condiciones TypeScript.

Regresión completa: 526 pruebas pytest y 121 subtests, 12 checks ligeros, cuatro
tests del cliente Node y check TypeScript del frontend. La suite existente cubre
sin cambios los esquemas/migraciones y sincronización OpenAPI. No se requiere
regenerar tipos ni cambiar API/UI; esquema `0013_bootstrap` y codec conservados.

## Límites

El puerto `FixtureCommandRunner` es de prueba para este checkout sintético
confiable. Demuestra procesos reales por el protocolo existente; no se añade un
adaptador de comandos de producto ni se certifican recuperación de procesos de
validación tras caída, aislamiento físico, cancelación o permisos de una CLI real.
La configuración de un puerto real sigue siendo responsabilidad de la composición
explícita del servidor. ReferenceProject permanece caracterizado con fakes, sin ejecutar
Django/Docker ni acceder a ese proyecto.

El test de interacción usa un DOM mínimo, sin navegador ni HTTP; el build se
comprueba como artefacto estático. Sin JUnit, cobertura por test o formatter
automático. El bootstrap H4.2 sigue creando documentos; este perfil no incorpora
otra plantilla de bootstrap ni genera una app desde un brief.

Sin proveedores, smokes, login, red externa, configuración global, SQLite de
trabajo, colaboración automática, uso del harness para desarrollar, push o
publicación. H5.1 importación JUnit queda siguiente, sin iniciarla. Decisión D038.
