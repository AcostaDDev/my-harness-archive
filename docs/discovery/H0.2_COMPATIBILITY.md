y Node 24. Node 24.15 supera el requisito de Vite `^20.19.0 || >=22.12.0`.
SQLite se usará mediante `sqlite3` de Python, sin servicio externo; registrar
también la versión enlazada en el preflight, no deducirla de la versión Python.

[Snapshot de metadatos y resolución](h0.2-version-metadata.json): incluye
`requires_python`, dependencias Python sin extras, engines/peers npm y peers
opcionales. Se resolvieron conjuntamente los ocho pins Python (27 paquetes)
para CPython 3.14.4 / `aarch64-apple-darwin`, solo wheels, sin construir fuentes
ni descargar Python. npm resolvió los diez pins UI (102 entradas) con
`--package-lock-only --ignore-scripts --strict-peer-deps --engine-strict
--no-audit --no-fund`, en directorio temporal con caché/config propios.
Exit code cero en ambos; sin `node_modules`, venv ni instalaciones del producto.

Esto demuestra disponibilidad y resolución de restricciones, **no** imports,
compatibilidad de comportamiento, arranque, build ni ejecución de Playwright.
El snapshot no sustituye `uv.lock`/`package-lock.json`: se crearán al incorporar
el esqueleto, conservando estos pins y comprobando instalación y build reales.
No se añaden ahora dependencias SDK ni scripts npm/servicio inexistentes.

## Matriz de capacidades

«Local» significa versión/help, sin inferencia; «documentada» significa fuente
oficial consultada; ninguna capacidad de agente se ensayó con una cuenta real.

| Capacidad | Codex exec 0.161.0 | Claude CLI 2.1.295 | App Server / Agent SDK |
|---|---|---|---|
| Salida | Local: `--json` JSONL; `--output-schema`; `--output-last-message` | Local: `-p`, `--output-format json\|stream-json`, `--json-schema` | Codex: JSON-RPC bidireccional sobre stdio JSONL; otro protocolo. Claude SDK: mensajes tipados, no probado |
| Streaming | Documentado: `thread.started`, `turn.*`, `item.*`, `error`; stdout separado de stderr | Documentado: `--verbose --include-partial-messages`, `stream_event`, final `result` | Documentados eventos, no integrado |
| Fin / error | `turn.completed` / `turn.failed`; conservar error y exit code | `result`, `subtype`, `is_error`; conservar error y exit code | Requiere contrato propio; fuera de la sonda |
| Modelo / esfuerzo | Local: `--model`; configuración por intento; efectivo solo si reportado | Local: `--model`, `--effort low\|medium\|high\|xhigh\|max` | No equiparar esfuerzos de proveedores ni deducir acceso por catálogo |
| Telemetría | Documentado: `usage` final; campos ausentes quedan ausentes | Documentado: metadatos de resultado; no asumir `modelUsage`, duración o coste en todas las salidas | No hay mediciones reales en H0.2 |
| Sesiones | Local: resume/fork, ephemeral; MVP inicia sesión nueva | Local: resume/continue/fork, no-session-persistence; MVP inicia sesión nueva | Chat independiente de intentos; integración posterior |
| Permisos | Local: sandbox read-only/workspace-write; `--ask-for-approval never` evita preguntas | Local: `dontAsk`, `--permission-prompts none`, tools/allowedTools/disallowedTools | Codex: requestApproval documentado. Claude: canUseTool condicionado por política; no siempre invocado |
| Aprobación web viva | No declarada para exec | No declarada para CLI inicial; denegación no es petición pendiente | Potencial de ambos documentado, no probado ni habilitado |
| Cancelación | Supervisor deberá cancelar grupo de procesos; sin prueba aquí | Igual; sin prueba aquí | Codex documenta turn/interrupt; SDK por evaluar |
| Reintento / fallback | La sonda no llama ni reintenta | `--fallback-model` existe: no usarlo en el adaptador | Reintentos internos de CLI/proveedor aún no caracterizados; no prometer cero llamadas por comprobar help |

Fuentes: [referencia CLI Codex](https://learn.chatgpt.com/docs/cli/reference),
[exec y eventos](https://learn.chatgpt.com/docs/non-interactive-mode),
[CLI Claude](https://code.claude.com/docs/en/cli-reference),
[headless y streaming Claude](https://code.claude.com/docs/en/headless).
El help local de Claude usa `manual` entre sus modos; no copiar valores de
otras versiones/SDK que usen `default`. La futura construcción de argv debe
respetar el binario fijado y no reutilizar automáticamente los flags legacy.

`dontAsk` transforma permisos no resueltos en denegaciones; no llama
`canUseTool` para esas peticiones. Las autorizaciones previas pueden permitir
herramientas sin callback. Para la CLI inicial, «Conceder» autoriza el siguiente
intento, seguido de una sesión nueva explícita. `allowedTools` preautoriza;
`--tools` define herramientas disponibles; ninguno sustituye por sí solo el
aislamiento de archivos/red. [Política SDK](https://code.claude.com/docs/en/agent-sdk/permissions).

`codex app-server --help` confirma transporte `stdio://` por defecto y comandos
de generación de schemas. No se inició el servidor ni se generaron bindings.
Su documentación describe aprobación por identificador y autenticación
ChatGPT administrada por Codex; eso permite mantenerlo como candidato para
H4.1. Faltan handshake, schemas exactos del binario, expiración de peticiones,
cancelación, recuperación y prueba de cuenta. [App Server](https://learn.chatgpt.com/docs/app-server).

## Autenticación y cuentas previstas

El usuario confirmó en esta sesión: **usar las suscripciones de cada usuario,
con las CLI ya autenticadas en su ordenador**. No se solicitan correo, ID de
cuenta, plan exacto ni tokens: no son necesarios para H0.2. No cambiar a API
de pago ni a otro proveedor cuando una suscripción falle o agote cuota.

| Adaptador | Modo previsto | Observación en esta sesión | Límite |
|---|---|---|---|
| Codex CLI | Login ChatGPT propio, gestionado por Codex | `codex login status`: exit 0, método ChatGPT; salida filtrada en memoria | No prueba cuota, modelo concreto ni vigencia con inferencia |
| Claude CLI | Login Claude propio, gestionado por Claude Code | Usuario confirma uso autenticado. En sandbox, `claude auth status --json`: exit 1, `loggedIn:false`, `authMethod:none`, `apiProvider:firstParty` | Resultado restringido no acredita sesión; tampoco prueba ausencia de login en el Mac. No se accedió directamente al llavero para resolverlo |
| Codex App Server | Candidato: login ChatGPT gestionado por Codex | Solo help y documentación | No implementar extracción/transferencia de tokens ni login propio en H0.2 |
| Claude Agent SDK | No seleccionado para este MVP por suscripción | No instalado ni autenticado | La documentación de terceros exige API salvo aprobación previa; reevaluar antes de activarlo |

Codex admite ChatGPT y API key con facturación distinta; access tokens
empresariales son otra opción documentada, no una cuenta solicitada aquí.
[Autenticación Codex](https://learn.chatgpt.com/docs/auth).
Claude Code documenta suscripción Pro/Max/Team/Enterprise, Console y proveedores
cloud; son modos distintos, no equivalencias con el plan del usuario.
[Autenticación Claude](https://code.claude.com/docs/en/authentication).

La documentación legal actual de Claude distingue ejecutar el binario publicado
con credenciales propias del usuario de ofrecer un login claude.ai propio en
un SDK. La primera vía contempla suscripción del usuario, con sus condiciones;
no modifica el binario ni intermedia consumo. La documentación del SDK conserva
la restricción para terceros salvo aprobación. Se mantiene CLI primero y SDK
sin habilitar; antes de distribuir o añadir login propio habrá que revisar esa
distinción. [Condiciones de integración CLI](https://code.claude.com/docs/en/legal-and-compliance),
[alcance del SDK](https://code.claude.com/docs/en/agent-sdk/overview).

Solo se conservaron campos permitidos de los comandos de estado. No se leyeron
archivos de credenciales ni se imprimieron correos, IDs, claves o tokens; no se
ejecutaron login/logout/setup-token ni se creó un flujo de autenticación.
