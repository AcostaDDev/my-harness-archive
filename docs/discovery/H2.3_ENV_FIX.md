## Cambio y diagnóstico previo al consumo

`scripts/smoke_cli.py` construye una única tupla de entorno con las variables
presentes de `HOME`, `PATH`, `TMPDIR`, `LANG` y ahora `USER`. Comprueba USER
contra `pwd.getpwuid(os.getuid()).pw_name`, consultando el usuario local del UID
del proceso, sin confiar en LOGNAME ni en un helper de autenticación.

USER ausente, vacío, inválido o distinto del usuario local detiene el script
con exit 2 y diagnóstico concreto. Un UID no resoluble también detiene el
script. La comprobación sucede después de la guardia de consentimiento y antes
de crear directorios/checkout, resolver CLI, ejecutar preflight o consumir.
El usuario debe corregir su contexto antes de una ejecución autorizada; no se
rellena USER silenciosamente ni se intenta login como reparación.

El entorno se entrega explícitamente a ambas CLI. No se heredan variables de
credenciales, selectores de proveedor, LOGNAME ni fuentes de configuración.
El adaptador sigue aceptando el entorno completo aportado por su llamador;
no añade USER ni consulta el entorno del supervisor. Su comportamiento, argv,
codec y esquema permanecen en `cli-3`/formato 2/`0005_cli_processes`.

Se conservan modelos/esfuerzos explícitos, timeout 60 s, sesiones nuevas,
herramientas vacías, MCP estricto vacío, fuentes vacías/hooks desactivados y
denegación dontAsk. El adaptador no relanza ni cambia selección al fallar;
los retries internos de las CLI continúan desconocidos.

sintético `smoke_environment_probe.py`, sin importar la lógica del constructor

  verifica selección, argv, permisos, sesiones frescas, hashes y persistencia
  tras reabrir SQLite. El job anterior rechaza la configuración corregida antes
  del preflight; filas SQL exactas, historial, resultados, specs, eventos, lock
  y bytes de capturas permanecen idénticos, sin lanzar más procesos.

Se inspecciona el entorno exacto en la frontera Popen para preflight y ejecución,
y el entorno observado por el hijo: HOME/PATH/TMPDIR/LANG conservados, USER
explícito y variables sintéticas de credenciales/configuración excluidas.

runtime; esas dos claves no forman parte del mapping aportado al proceso.
La prueba distingue esa adición del runtime de herencia del supervisor.
