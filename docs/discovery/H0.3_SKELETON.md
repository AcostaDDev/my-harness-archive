# H0.3 — Esqueleto y límites comprobados

Completado el 2026-10-11. [Alcance original](H0.3_SCOPE.md).
Git comenzó limpio en `main`; entrega local sin commit. H1.1 no se inicia.

## Recorrido implementado

`POST /api/simulations` valida el título, llama al caso de uso del núcleo y
ejecuta el adaptador falso. El resultado completo y sus tres mensajes se
guardan en una única transacción SQLite. `GET /api/simulations` y
`GET /api/simulations/{id}` consultan ese historial; `/api/health` comprueba
acceso a la tabla. React permite crear y seleccionar simulaciones.

La simulación es síncrona e inmediata: no inicia un job, proceso, proveedor,
checkout ni intento de agente. `completed` solo significa que terminó esta
simulación. No hay aceptación, commit, consumo, modelo ni telemetría inventada.
No se implementan aún cola, supervisor, exclusión por checkout ni recuperación
de intentos; pertenecen a H2 y este recorrido no modifica código de proyectos.

| Capa | Implementación y límite |
|---|---|
| Núcleo | `src/harness_local/core`: dataclass inmutable, protocolos y caso de uso; solo biblioteca estándar |
| Adaptador | `adapters/fake.py`: tres mensajes sintéticos, sin red ni procesos |
| Almacenamiento | SQLAlchemy, tabla `simulations`, fecha ISO UTC y mensajes JSON; SQLite es la única autoridad |
| Migración | Alembic `0001_simulations`, upgrade/downgrade; no `create_all` ni migración implícita al arrancar |
| HTTP | Pydantic y FastAPI; rechaza título vacío/largo, tipo inválido y propiedades extra; 404 para ID ausente |
| Cliente | Tipos de `api.generated.ts` generados desde el OpenAPI exportado; sin contratos de dominio duplicados |
| UI | React/TypeScript/Vite; carga, errores, historial, selección y resultado; sin assets externos |

El servicio se enlaza a loopback y usa un solo proceso. SQLite configura WAL,
foreign keys, busy timeout de 5 segundos y control transaccional moderno de
`sqlite3` (`autocommit=False`). Ninguna transacción está abierta mientras el
adaptador produce su resultado. El arranque exige la revisión de esquema
conocida; las migraciones se ejecutan explícitamente con el servicio detenido.

## Instalación real y contratos

Se comprobaron Python 3.14.4, uv 0.12.19, Node 24.15.0 y npm 11.12.1 en
macOS ARM64. Se conservan los pins directos de H0.2 para las dependencias usadas.
`uv.lock` contiene 28 entradas incluido el paquete local; se instalaron 27
paquetes en `.venv`. `package-lock.json` fija la UI y se instalaron 55 paquetes
en `frontend/node_modules` con `npm ci --ignore-scripts`.

Se añade `uv_build==0.12.19` como backend para instalar el paquete `src/`;
la construcción editable se comprobó al sincronizar. No se añaden PyYAML,
Vitest ni Playwright porque H0.3 no los usa. pytest y HTTPX sí se usan en las
pruebas HTTP/persistencia. Esto es instalación/ejecución real, separada de la
resolución sin instalación de H0.2.

La exportación OpenAPI no conecta SQLite ni arranca la aplicación. Los
artefactos versionados son `frontend/openapi.json` y `frontend/src/api.generated.ts`.
Se comprobaron la coincidencia exacta con el esquema del runtime y la
regeneración determinista de los tipos. `npm run check` comprueba el cliente;
`npm run build` comprueba tipos y produce los assets locales.

Fuentes primarias consultadas para la implementación:
[TestClient de FastAPI](https://fastapi.tiangolo.com/tutorial/testing/),
[transacciones SQLite en SQLAlchemy](https://docs.sqlalchemy.org/en/20/dialects/sqlite.html),
[Alembic](https://alembic.sqlalchemy.org/en/latest/tutorial.html) y
[backend de uv](https://docs.astral.sh/uv/concepts/build-backend/).
Los comandos comprobados están en [README](../../README.md) y [AGENTS](../../AGENTS.md).

## Verificación y criterios

- 12 checks de biblioteca estándar anteriores: correctos, sin dependencias,
  procesos ni red, con `python3 -m unittest discover -s tests -p 'test_*.py' -v`.
- `uv run --frozen --offline pytest -q`: 26 pruebas correctas y 121 subtests
  (12 anteriores + 14 casos H0.3). Incluye importación del núcleo con `python -S`,
  frontera de imports, adaptador sin procesos, error sin guardado/reintento,
  validación, persistencia entre dos aplicaciones y ausencia de telemetría falsa.
- Upgrade a head, `alembic current`, `alembic check`, downgrade a base y nuevo
  upgrade: correctos sobre bases sintéticas; WAL y foreign keys comprobados.
- Generación de contratos, TypeScript y build Vite: correctos. Assets:
  HTML 0,44 kB, CSS 4,10 kB, JS 223,78 kB (aproximados, antes de compresión).
- Uvicorn arrancó y sirvió API/UI compilada en `127.0.0.1:8013`. Chrome mostró
  el estado vacío, creación por formulario, resultado completado con tres
  eventos y conservación del mismo ID tras detener/reiniciar Uvicorn y recargar.
- Vite arrancó en `127.0.0.1:5173`; al abrirlo en Chrome su proxy solicitó el
  historial a la API con respuestas 200. La comprobación completa del contenido
  visible se hizo sobre la UI compilada. No hubo captura visual: ScreenCaptureKit
  falló; se verificó el recorrido por el árbol de accesibilidad y logs HTTP.
- Locks reales, reinstalación desde caché, diff/whitespace y comandos locales
  revisados. Los servicios temporales de verificación quedaron detenidos.

Los cuatro criterios de H0.3 están cumplidos: aplicación/API/UI ejecutadas con
simulación local, núcleo independiente, migración/persistencia verificadas y
locks/install/build/checks comprobados. Solo se afirma este esqueleto.

## Incidencias y límites

El sandbox bloqueó DNS para PyPI/npm y bind a puertos locales; tras aprobación
se descargaron dependencias y abrieron los servicios de prueba. No se modificó
configuración global; las cachés se mantuvieron bajo `.local`. El puerto 8000
estaba ocupado y no se tocó su servicio; se adoptó 8013 para esta aplicación.
uv observó un entorno activo de otro proyecto y lo ignoró, usando `.venv` aquí.

Starlette 1.7.0 emite un aviso de deprecación de TestClient con HTTPX 0.28.1 y
sugiere HTTPX2. Los pins de H0.2 se conservan y las pruebas pasan; el aviso no
se oculta. Revisar esa dependencia al volver a modificar las pruebas HTTP.

No se probaron otros sistemas, carga/concurrencia, modelos, CLI reales, cuotas,
permisos vivos, cancelación, SSE, importador, motor ni distribución. No se
ejecutaron harness, agentes, SDKs, tests/instalaciones de ReferenceProject, push o
publicación. El historial de prueba sintético queda en SQLite local ignorada.
