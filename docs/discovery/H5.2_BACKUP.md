# H5.2 — Backup y restauración local

Completado y verificado offline el 2026-10-13. [Alcance original](H5.2_SCOPE.md),
D040. Entrada de biblioteca en `storage/backup.py` y tres comandos CLI; sin
adaptadores de ejecución, dependencias nuevas ni migración. Esquema
`0013_bootstrap`, historial formatos 1–6.

## Procedimiento

1. Detener el servicio, su observador y todos los escritores de los checkouts y
   artefactos. Un apagado de Uvicorn puede terminar antes que el job: comprobar
   también los grupos de procesos. El vencimiento del lease no demuestra parada.
2. Elegir un destino **nuevo, inexistente**, cuyo padre ya exista, fuera de los
   checkouts y de las raíces de artefactos. No se reutilizan directorios vacíos
   existentes ni copias incompletas. Proporcionar la SQLite y cada raíz de
   artefactos explícitamente; no se usa `HARNESS_DATABASE_URL` para copiar.
3. Crear, verificar y restaurar. Ejemplo de uso con rutas que el operador debe
   sustituir por las de su almacenamiento local; no se ejecutó sobre datos reales:

```sh
UV_CACHE_DIR=.local/uv-cache uv run --frozen --offline python -m harness_local.cli backup-create /ruta/local/state.sqlite3 /ruta/copias/copia-001 --artifact-root /ruta/local/artifacts --artifact-root /ruta/local/migrations --writers-stopped
UV_CACHE_DIR=.local/uv-cache uv run --frozen --offline python -m harness_local.cli backup-verify /ruta/copias/copia-001
UV_CACHE_DIR=.local/uv-cache uv run --frozen --offline python -m harness_local.cli backup-restore /ruta/copias/copia-001 /ruta/restauraciones/consulta-001
UV_CACHE_DIR=.local/uv-cache uv run --frozen --offline python -m harness_local.cli backup-verify /ruta/restauraciones/consulta-001
```

`--artifact-root` es repetible y delimita las lecturas permitidas. Se copian solo
las referencias gestionadas conocidas dentro de esas raíces. Si no hay ninguna,
no hace falta declararlas. Referencia fuera de las raíces, archivo requerido
perdido/cambiado o copia incompatible → exit 1 y diagnóstico por stderr. No se
omiten evidencias requeridas ni se reparan sus hashes. Los comandos exitosos
imprimen el manifiesto JSON, incluido el inventario de runs con sus IDs/estados.

La biblioteca ofrece `create_backup`, `verify_bundle`, `restore_backup` y
`restored_artifact(engine, ruta_histórica)`. Este último resuelve una referencia a
su archivo copiado; la verificación completa corresponde a `verify_bundle`.

## Consistencia y contenido

`--writers-stopped` es una declaración explícita de parada, no una acción que
mate procesos. Un propietario abierto o grupo conocido observado vivo rechaza
la copia. Identidades inaccesibles/desconocidas permanecen inciertas y requieren
que el operador compruebe la parada por su cuenta. No se señalan PIDs históricos.

La conexión obtiene `BEGIN IMMEDIATE` y mantiene el bloqueo escritor SQLite hasta
sellar el bundle. Otra conexión usa `sqlite3.Connection.backup`: incluye los
commits del WAL sin copiar únicamente el fichero principal. Un escritor DB que
compita encuentra el bloqueo. No equivale a pausar un agente que ya estaba
escribiendo archivos; por eso el servicio y sus escritores deben estar detenidos.
Cada artefacto se comprueba contra su referencia y se relee al terminar el conjunto.
Los cambios detectados invalidan la copia. La exclusión frente a herramientas
externas sigue siendo cooperativa.

Se conservan todas las tablas y filas: historial, contextos/snapshots, prompts,
permisos/consumos, fases/definiciones/preguntas/autorizaciones, chat, bootstrap,
intenciones Git, jobs/locks/propietarios/procesos y observaciones legacy. Los
originales JUnit ya están en SQLite y se comprueban por base64/hash/tamaño.
No se reescriben raíces, contratos, selecciones ni versiones congeladas.

Artefactos externos incluidos:

- `prompt.txt` de cada intención CLI, con su hash congelado;
- `stdout.bin`/`stderr.bin`, con hashes/tamaños finales y rangos/hash de eventos;
- bytes de streams interrumpidos, incluida la cola aún sin checkpoint; esa cola
  se conserva sin convertirla en eventos o resultados inferidos;
- archivos de snapshots H2.5 declarados en su manifiesto y en el índice SQLite;
- exportación de reversión H2.5 referenciada, con su hash registrado.

Un stream que no llegó a producir bytes ni a registrar una captura puede estar
pendiente/ausente: el manifiesto lo declara en `absent_optional`. Si existe un
rango observado o una captura final, su archivo es obligatorio. Los documentos,
parches Git y previews que ya son payloads SQLite se conservan dentro de ella.

H5.3 añade la excepción auditada `absent_purged` para originales stdout/stderr
retirados por política explícita; se contrasta con intenciones/resultados del
journal. Una pérdida sin esa prueba sigue siendo un error, y una intención
pendiente impide publicar backup. [Política, consulta y recuperación](H5.3_RETENTION.md).
Los bundles anteriores sin purgas conservan su formato y verifican sin el campo.

## Bundle, integridad y restauración

El destino se reclama con creación exclusiva. Contiene `state.sqlite3`,
`artifacts/NNNNNN.bin`, `manifest.json` (formato 1) y `COMPLETE` con el SHA-256 del
manifiesto. Cada archivo tiene hash/tamaño y mapeo de ruta histórica/procedencia.
Directorios 0700 y archivos 0600; escrituras exclusivas, fsync de archivos y
carpetas. Un fallo puede dejar un directorio parcial para inspección, que nunca
se reutiliza ni cuenta como copia completa. No hay limpieza automática.

El verificador comprueba hashes, rutas, unicidad y correspondencia exhaustiva
con las referencias SQLite, esquema/tablas/columnas, `integrity_check`, foreign
keys, codec y originales JUnit. Rechaza WAL/journal no vacíos en el bundle:
la SQLite sellada debe ser autosuficiente. Esquema/formato futuro o historial
ilegible producen diagnóstico; nunca se ejecuta una migración implícita.
Las rutas históricas son datos: verificar/restaurar no consulta sus originales,
aunque estos se hayan eliminado o convertido posteriormente en enlaces.

Restaurar verifica primero el bundle entero, copia exclusivamente a un destino
nuevo y vuelve a verificar los archivos leídos y el resultado. Conserva la copia
y el origen. El manifiesto restaurado identifica su origen por hash. Tanto el
backup como la restauración llevan una marca interna en `PRAGMA user_version`
(`0x483532`), distinta de la revisión Alembic. Las filas operativas permanecen
idénticas; la marca protege incluso si se mueve solo la SQLite.

`make_engine` abre esas bases con `query_only=ON`; versiones de marca desconocidas
se rechazan. La API comprueba el bundle al arrancar, no carga configuración
gestionada ni inicia supervisor/observador. Todas sus mutaciones devuelven 409
`restored_read_only`. La biblioteca también rechaza escrituras antes de reclamar
jobs. No convierte ACTIVE/RECOVERY_REQUIRED en DONE/STOPPED ni libera locks;
no revive autorizaciones, repite commits o lanza agentes.

## Consultas y límites

El manifiesto enumera los runs. Se pueden consultar por sus IDs mediante las
rutas existentes de lectura: `/api/managed/runs/{id}`, jobs, intentos, eventos,
casos JUnit y descarga de su original. El índice legacy conserva sus proyectos
históricos; su endpoint de contenido resuelve los snapshots copiados y comprueba
sus bytes contra el hash indexado. No vuelve a una fuente externa si falta un
mapeo. API en modo consulta, usando el bundle completo y su SQLite:

```sh
HARNESS_DATABASE_URL=sqlite:////ruta/restauraciones/consulta-001/state.sqlite3 UV_CACHE_DIR=.local/uv-cache uv run --frozen --offline uvicorn harness_local.api.app:create_app --factory --host 127.0.0.1 --port 8013 --workers 1
```

Las rutas de lectura anteriores no requieren que existan los checkouts. La API
no registra proyectos gestionables desde snapshots: esas configuraciones y los
checkouts no son parte del backup; las consultas gestionadas se hacen por ID.
No hay reactivación operativa ni botón para retirar la guardia en H5.2. Reanudar
trabajo exigiría un procedimiento separado que verificara checkouts, procesos,
intenciones y autorizaciones; restaurar evidencia no concede ese permiso.

No se copian repositorios/worktrees Git, credenciales/configuración global,
fuentes legacy externas ni temporales no referenciados. Los IDs Git se conservan
como referencias históricas; para recuperar el código/objetos Git hace falta su
propia copia. El manifiesto enumera los orígenes legacy externos, cuyo índice se
conserva pero cuyos cuerpos siguen siendo autoridad externa. No se reconstruyen
originales ausentes ni archivos de migraciones parciales aún no publicados.

Límites: 256 MiB por fichero (incluida SQLite), 2 GiB de artefactos en conjunto,
10.000 referencias y 4 MiB de manifiesto. Lecturas por bloques, acotadas y con
O_NOFOLLOW en todos los componentes; no siguen enlaces simbólicos/duros ni leen
FIFO/dispositivos. Cada archivo se materializa en memoria dentro de su límite.
No se ha medido gran volumen ni certificado otra plataforma. Los hashes no son
una firma contra el propietario del equipo. Sin retención/GC, cifrado, archivo
comprimido, distribución o configuración portable en esta entrega.

## Verificación

43 casos nuevos: WAL real; filas/contextos/historial/eventos exactos; JUnit y
consulta HTTP tras borrar su XML; streams Python sintéticos finalizados o
inciertos, rangos/colas/ausencias; snapshots y exportación H2.5; consultas legacy
sin originales; guardia DB/API incluso con supervisor configurado o fichero
movido; escritor concurrente rechazado; errores, corrupción/versiones/FK,
manifiestos/rutas/enlaces/FIFO/límites, deriva durante copia/restauración y destinos
ocupados. Recorrido CLI copia → verificación → restauración → verificación.

Regresión final: 612 pruebas pytest y 121 subtests, 12 checks ligeros y cuatro
pruebas Node; TypeScript/build correctos. Los checks existentes de migraciones y
sincronización OpenAPI pasan; contratos HTTP, esquema/codec y locks de dependencias
sin cambios. Aviso conocido Starlette/HTTPX conservado. No se lanzaron servicios
en navegador, proveedores, smokes ni agentes; no se migró ni copió la SQLite de
trabajo. Solo bases, checkouts y artefactos sintéticos. H5.3 no iniciado.
