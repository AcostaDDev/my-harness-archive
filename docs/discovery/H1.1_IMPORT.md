# H1.1 — Importación legacy de lectura

Completado: 2026-10-11. [Alcance original](H1.1_SCOPE.md).
Solo fixtures sintéticos H0.1; no se leyó el repositorio de referencia ni sus runs.

## Entrega

- `core/legacy.py`: inventario de evidencias, protocolos y caso de uso; biblioteca
  estándar, sin proveedores, web ni procesos. Un run importado es un directorio
  observado; ninguna iteración de review/validación se convierte en invocación.
- `adapters/legacy.py`: lectura explícita de cada raíz de checkout, `.harness/runs`
  y `docs/{STATE,NEXT_STEPS,ROADMAP}.md` / `docs/archive`. Conserva objetos JSON
  completos y eventos JSONL desconocidos; indexa textos/logs/diffs por ruta,
  SHA-256 y tamaño. No usa el manifest de fixtures como contrato del producto.
- `storage/legacy.py`: índice atómico por origen con tablas `legacy_sources`,
  `legacy_runs` y `legacy_artifacts`; migración `0002_legacy_index`. Las claves
  son raíz canónica + ruta relativa. La identidad del run procede de su nombre;
  IDs de tarea/fase permanecen en sus payloads sin forzar coincidencias ni schemas
  actuales sobre contratos antiguos. El hash describe los bytes realmente leídos.
- `cli.py`: `legacy-import CHECKOUT` relee explícitamente y devuelve resumen JSON;
  `legacy-summary CHECKOUT` consulta únicamente el índice. SQLite y esquema se
  comprueban antes de importar; no hay migración automática ni servidor necesario.
  La base debe estar fuera del origen, comprobado antes de abrirla desde la CLI.
- `storage/schema.py`: revisión esperada compartida por API/CLI. La simulación
  H0.3 continúa funcionando con el esquema nuevo y conserva su contrato HTTP.

El índice conserva la última observación por ruta; no es un historial adicional
ni autoridad sobre las tareas. Reimportar reemplaza contenido/hash/diagnóstico
sin duplicar filas. Mantiene runs conocidos y marca evidencias desaparecidas como
`missing`, retirando el payload/hash actual; los archivos originales conservan el
historial real. Se puede reconstruir SQLite desde esos archivos. La fecha de
observación del origen queda en UTC, sin atribuirla al inicio/fin de un agente.

## Ausencias y diagnósticos

`available` indica lectura/parseo, no éxito de ejecución. `pending` indica
JSON/UTF-8 inválido o JSONL incompleto que requiere relectura; `error` identifica
errores locales de lectura/estructura. Ninguno se interpreta como error del modelo.
Un diagnóstico de un archivo no impide indexar el resto. JSONL parcialmente
parseado conserva su prefijo de objetos; el hash siempre corresponde al archivo
completo leído. Los enlaces simbólicos se diagnostican sin seguirlos.

`missing` describe evidencia no observada. Para cada índice con evidencia
Claude se enumeran sus compañeros request/events/result/usage/prompt/stderr;
para índices de evidencia se enumeran review/validation/stop; tareas y runs de
fase añaden sus JSON conocidos. Son referencias de observación, **no** requisitos
que necesariamente debía producir un run. También se conservan las ausencias de
archivos anteriormente indexados. No se crean invocaciones ni se deduce un fallo
por estos compañeros ausentes; un stop no es una review.

El resumen añade observaciones de consumo/duración/petición con `state`:
`absent`, `null` o `recorded`. Ausente y null llevan la etiqueta «no registrado»;
null conserva `value: null`, cero registrado conserva `value: 0`. Se aplica también
a la duración de cada comando de validación. El payload original mantiene todos
los campos y su procedencia, sin defaults de modelo/esfuerzo ni estimaciones.
Los valores de coste conservan sus nombres legacy (coste equivalente API), sin
convertirse en facturación de suscripción. ACCEPT/READY permanecen como valores
de los archivos; no certifican aceptación aplicada, commit ni cierre.

Los `synthetic-git-log.txt` de los fixtures son extractos auxiliares externos al
formato legacy y no se importan como certificados Git. No se leen configuraciones,
credenciales, fuentes del proyecto, ni se ejecutan prompts o comandos históricos.

## Límites

No se arrancaron servidores ni se repitió el recorrido de navegador H0.3;
regresión automatizada y build comprobados. Persiste el aviso upstream de
Starlette/TestClient con HTTPX 0.28.1; no se cambió el pin H0.2. uv ignora el
entorno activo externo y usa `.venv` del repositorio.

No hay entidades gestionadas, historial de versiones del índice, watcher/SSE,
navegación H1.2, ejecución, recuperación Git, migración de autoridad ni prueba de
escritores concurrentes. H1.1 tolera lecturas parciales, pero no acredita snapshots
consistentes de un checkout activo. No se usaron red, proveedores, agentes,
harness, datos reales ni configuración global. Decisión D012.
